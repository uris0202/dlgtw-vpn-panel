# Смена IP VPN-сервера через DLGTW VPN Panel

## Что нужно согласовать при смене IP

Если провайдер изменил адрес прежней машины, UUID клиентов, срок доступа и ключи Reality обычно сохраняются. Для каскада необходимо согласовать три состояния:

1. Адрес 3X-UI в существующей записи сервера в базе панели.
2. Адрес и VPN-порт в relay/routes.json и relay/haproxy.cfg.
3. Адрес, который использует уже работающий HAProxy.

Редактирование файлов само по себе не меняет память запущенного HAProxy. Кроме того, при старом одиночном bind mount замена файла редактором могла оставить контейнеру прежний экземпляр файла. Это обновление монтирует каталог и применяет новые адреса через штатный локальный HAProxy Runtime API, сохраняя конфигурацию для последующих запусков.

Если нужно применить уже отредактированный файл до установки веб-управления, сначала проверить именно файл хоста, затем пересоздать только relay:

```sh
cd ~/vpnpanel
docker run --rm --network none --cap-drop ALL --read-only -v "$PWD/relay/haproxy.cfg:/tmp/haproxy.cfg:ro" haproxy:3.0-alpine haproxy -c -f /tmp/haproxy.cfg
docker compose --profile relay up -d --no-deps --force-recreate vpn-relay
```

Вторую команду выполнять только после успешной проверки конфигурации. Адрес 3X-UI в существующей записи сервера на сайте также должен быть обновлён. Такой перезапуск relay требует переподключения текущих VPN-сессий.

## Однократная установка

ZIP загрузить в /root Петербургского сервера. Сначала сохранить исходные файлы:

```sh
cd ~/vpnpanel
umask 077
mkdir -p ~/vpnpanel-backups
STAMP=$(date +%Y%m%d-%H%M%S)
tar --exclude='./frontend/node_modules' --exclude='./frontend/.next' --exclude='./backups' --exclude='./.git' --exclude='./relay/control' -czf ~/vpnpanel-backups/pre-web-relay-files-$STAMP.tar.gz .
```

Затем:

```sh
unzip -o ~/vpn-relay-web-control-20261030.zip -d ~/vpnpanel
sh scripts/enable-relay-web-control.sh
```

Установщик делает резервную копию PostgreSQL и файлов каскада в ~/vpnpanel-backups/web-relay-ДАТА, собирает backend/frontend и запускает тесты. Затем проверяет конфигурацию HAProxy, создаёт локальный управляющий сокет и проверяет, что backend может прочитать реальные адреса работающих маршрутов. Миграции БД не нужны.

Первичная установка перезапускает relay/backend/frontend и Caddy; активным VPN-соединениям может потребоваться переподключение. Последующие обновления существующих маршрутов через сайт выполняются без общего перезапуска HAProxy.

Управляющий сокет не публикуется в интернет. Он находится в закрытом каталоге, доступном root и группе backend. Docker socket в backend не передаётся. Каталог relay доступен backend для сохранения управляемых файлов, а HAProxy читает их через read-only mount с отдельным writable mount только для локального сокета.

## Как теперь поменять IP

1. На сайте открыть «Серверы», найти существующую запись Амстердама и нажать «Изменить».
2. В поле «Адрес панели 3X-UI» заменить только IP на 129.101.125.104. Сохранить прежние протокол и порт панели, Base path, логин и пароль.
3. Нажать «Сохранить». Для уже настроенного каскада панель автоматически попробует обновить маршрут.
4. При необходимости повторить проверку кнопкой «Обновить маршрут» в карточке сервера.
5. Проверить, что в карточке «Маршрут VPN» указан нужный адрес назначения и статус «Применён».

Если HAProxy до обновления считал узел недоступным, проверкам порта может потребоваться около 20 секунд, чтобы снова допустить соединения. При продолжающихся тайм-аутах сначала проверить реальную доступность нового порта, а не только статус применения адреса.

Например, если прежний URL панели был https://195.133.63.113:10000, новым будет https://129.101.125.104:10000. Если порт панели был другим, сохраняется именно он. Это не VPN-порт: порт VLESS читается из inbound в 3X-UI автоматически.

Для текущего каскада Амстердама публичный адрес клиента остаётся 139.100.235.247:24444, а адрес назначения должен стать 129.101.125.104:30001, если inbound по-прежнему слушает 30001. Поля server_id/inbound_id/listen_port и public_host сохраняются.

Сама ссылка единой подписки не меняется. В профилях, уже использующих Петербург, достаточно переподключить VPN. Старые прямые профили с иностранным IP требуют обновления в приложении.

## Проверки и ошибки

Перед применением панель проверяет авторизацию 3X-UI, наличие исходного активного VLESS inbound и два TCP-подключения к его порту. Затем меняет только соответствующий backend HAProxy, считывает адрес обратно и сохраняет routes.json и haproxy.cfg. Другие страны и публичные порты не меняются. Копии предыдущих файлов сохраняются в relay/history.

Если проверка не пройдена, маршрут не изменяется. Если ошибка возникла при применении или записи файлов, выполняется откат. Если сам откат не подтверждён, интерфейс сообщает, что необходима проверка HAProxy; ложного сообщения об успешном восстановлении нет.

Сохранение записи сервера и применение переадресации — два отдельных действия. Если адрес сохранён, но переадресация не прошла проверку, интерфейс показывает именно это и оставляет возможность повторить обновление маршрута. Прежняя настройка переадресации при этом может указывать на уже недоступный старый IP; она не объявляется гарантированно рабочей.

«Применён» означает согласованность адреса в конфигурации и работающем HAProxy. Это не гарантия отсутствия сетевых потерь и не проверка полного VLESS/Reality сеанса.

Для нового сервера или изменившегося номера inbound сначала требуется первоначальная настройка каскада. Веб-команда обновляет существующие маршруты; она не создаёт новые публичные listeners и не меняет тарифы.

## Важный результат проверки нового IP

На 129.101.125.104:30001 из Петербурга 30 октября 2026 года прошли две из трёх проб, одна завершилась TCP-тайм-аутом. Следовательно, новая адресация сама по себе пока не доказала устранение сетевой нестабильности. Пинг и SSH не заменяют проверку VPN-порта. Веб-управление решает согласованность конфигурации; маршрут/фильтрация сети требуют отдельного разбора с провайдером или проверки обходного пути.

## Проверка после установки

```sh
cd ~/vpnpanel
docker compose exec -T backend python -c 'from app.services.relay_admin_service import runtime_destinations; print(runtime_destinations())'
docker compose exec -T backend python - 12 --http-only < scripts/diagnose-vpn-subscription.py
```

Первый вывод показывает адреса, реально используемые HAProxy. Во втором ожидается status=200 и три профиля для соответствующего кабинета. Затем проверить каждую оплаченную страну из VPN-приложения.

Если прямые TCP-подключения к новому IP продолжают срываться, исправление конфигурации не является подтверждением стабильной передачи данных. Для поддержки есть результаты предыдущих проверок; новый IP также нужно указать в обращении.

## Откат обновления

Для возврата исходной версии использовать архив pre-web-relay-files-ДАТА.tar.gz, сохранённый перед распаковкой, затем пересобрать backend/frontend и пересоздать relay. Исходную конфигурацию каскада можно найти также в ~/vpnpanel-backups/web-relay-ДАТА. Перед восстановлением старого routes.json учитывать, не менялся ли IP сервера после создания этой копии. Восстанавливать PostgreSQL для отката этого обновления не требуется: схема БД не менялась.
