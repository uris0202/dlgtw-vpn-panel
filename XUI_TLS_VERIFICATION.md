# Историческая инструкция: обязательная проверка сертификатов

Этот документ описывает предыдущий строгий режим. По новому требованию он
заменён режимом предупреждений без блокировки API. Используйте
[актуальную инструкцию](XUI_TLS_WARNING_MODE.md) и архив
`xui-tls-warning-mode-20261101.zip`. Команды ниже относятся к старой версии;
повторно устанавливать старый архив не нужно.

Проверка с рабочего VDS подтвердила доверие к сертификатам сохранённых адресов
Germany, Amsterdam и Poland. Перевыпускать их или менять DNS для этого обновления
не требуется. Старое предупреждение появлялось потому, что интеграция DLGTW
использовала `verify=False`, а не потому, что сертификаты были признаны плохими.

## Изменения

- Все подключения через `XUIService` используют `verify=True`: проверяются
  цепочка доверия, срок действия и соответствие адресу подключения.
- При ошибке сертификата нет автоматического повторения с отключённой проверкой.
- Запросы 3X-UI не могут перенаправляться на другой origin (схема, хост, порт).
  Перенаправления между путями одного origin остаются разрешены. Это предотвращает
  отправку запросов управления по HTTP после HTTPS-подключения или на другой адрес.
- Зелёный статус «Защита канала управления» появляется после успешного HTTPS-входа.
  Если сеть или авторизация не сработали, TLS не объявляется успешным без подтверждения.
- Ошибка сертификата отображается отдельно, без паролей и закрытых адресов.
- VPN-ссылки, UUID, ключи REALITY, API-контракты и маршруты не меняются.

Поведение `verify=True` описано в [документации HTTPX](https://www.python-httpx.org/advanced/ssl/).

## Установка

Загрузите `xui-tls-verification-20261101.zip` в `/root/` рабочего VDS сайта.
Выполните на нём:

```sh
cd ~/vpnpanel &&
mkdir -p ~/vpnpanel-backups &&
umask 077 &&
tar --exclude='./.git' --exclude='./frontend/node_modules' \
    --exclude='./frontend/.next' --exclude='./backups' \
    --exclude='./relay/control/*.sock' \
    -czf ~/vpnpanel-backups/pre-xui-tls-$(date +%Y%m%d-%H%M%S).tar.gz . &&
unzip -o ~/xui-tls-verification-20261101.zip -d ~/vpnpanel &&
sh scripts/install-xui-tls-verification.sh
```

Копия проекта содержит `.env` и может содержать другие секреты — не публикуйте её.
Установщик дополнительно сохраняет `database.dump` и проверяет его оглавление
через `pg_restore --list`. Это не тестовое восстановление базы.

До замены работающих контейнеров новый образ проходит тесты и проверку
подключений ко всем включённым серверам: TLS, вход и чтение inbounds.
Эта проверка создаёт обычные сессии входа в 3X-UI, но не меняет настройки VPN.
Если какой-либо сервер не прошёл проверку, установщик остановится до пересоздания
контейнеров. Не включайте обратно `verify=False` и не продолжайте команды вручную:
пришлите результат проверки.

После успешной проверки обновляется только backend и перезапускается Caddy.
Панель в этот момент кратковременно недоступна. Frontend не пересобирается.
HAProxy и зарубежные Xray не перезапускаются, клиентские подключения не меняются.
Миграций базы нет.

Если часовой монитор уже установлен, его образ тоже обновляется.
Работающий монитор пересоздаётся с сохранением volume инцидентов; остановленный
монитор остаётся остановленным. Если монитор не установлен, этот пакет его не
устанавливает и не меняет `docker-compose.yml`.

## Результат

В конце должны появиться три результата:

```json
{"server_id":1,"server_name":"Germany","status":"verified","inbounds":1}
{"server_id":2,"server_name":"Amsterdam","status":"verified","inbounds":1}
{"server_id":3,"server_name":"Poland","status":"verified","inbounds":1}
```

Это пример формата; фактическое число inbounds может отличаться.
Итоговая полная диагностика записывается в:

```text
/root/vpnpanel-backups/xui-tls-ДАТА-ВРЕМЯ/diagnostics.jsonl
```

Откройте **Серверы → Диагностика** и запустите новую проверку.
В строке **Защита канала управления** должен быть статус **Успешно**.
Старый скачанный отчёт не обновляется. Предупреждения REALITY об отдельных
клиентах без Vision к этому обновлению отношения не имеют.

## Продление сертификатов

В присланной проверке сроки окончания были:

- Germany: 8 ноября 2026, 07:58:48 UTC.
- Amsterdam: 6 ноября 2026, 20:40:29 UTC.
- Poland: 8 ноября 2026, 05:14:46 UTC.

На 1 ноября сертификаты действуют. Этот отчёт не подтверждает настройку
автопродления: его нужно проверить в установленном у вас менеджере сертификатов
3X-UI/ACME. Короткий срок сам по себе не является ошибкой. Обновление DLGTW
не устанавливает и не меняет задачи продления на зарубежных серверах.

После истечения непродлённого сертификата панель намеренно перестанет доверять
такому API. Это не выключает автоматически Xray/REALITY, но операции управления
потребуют исправления сертификата. Часовой монитор, если работает, отметит сбой
API управления отдельно от TCP-доступности VPN.

который используется установщиком. Исходники предоставлены полными файлами.

Локальные проверки включают реальные TLS-рукопожатия с временным тестовым CA:
доверенный сертификат принимается, просроченный, недоверенный и выданный для
другого IP отклоняются до HTTP-запроса. Проверен запрет передачи POST-данных
при перенаправлении на другой origin. Production-доступ локально не проверялся;
его повторно проверяет установщик на сервере. Docker локально недоступен.
