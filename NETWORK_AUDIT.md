# Проверка сети DLGTW VPN

Подписка с тремя профилями уже выдаётся. Следующий шаг — проверить условия работы TCP-каскада и реальное подключение из сети клиента.

## Запуск на сервере сайта

Загрузить ZIP в /root, затем:

```sh
cd ~/vpnpanel
unzip -o ~/vpn-network-audit-20261030.zip -d ~/vpnpanel
sh scripts/audit-vpn-network.sh
```

Скрипт читает текущие настройки и счётчики. Он не меняет sysctl, firewall, MTU, маршруты или конфигурацию HAProxy и не перезапускает существующие контейнеры. Для TCP-проверки создаётся временный контейнер на уже установленном образе backend без паролей и .env, с той же сетью хоста, которую использует HAProxy. После проверки временный контейнер удаляется.

При проверке выполняется по три коротких TCP-подключения к каждому уникальному VPN-порту из relay/routes.json. UUID, VLESS-ссылки, токены подписки, пароли и IP подключённых клиентов не выводятся. В отчёте есть только адреса инфраструктуры, текущие системные параметры и агрегированные счётчики.

Резервная копия базы и пересборка для этой диагностики не требуются: данные панели не изменяются.

## Что смотрим

- Загрузку CPU, доступную память, swap и steal time виртуального сервера.
- Потребление ресурсов контейнерами и признаки OOM/restart HAProxy.
- Алгоритм TCP congestion control, очередь интерфейса, MTU и ограничения буферов.
- Ошибки и drops интерфейса, счётчики retransmission, переполнение очередей приёма и conntrack.
- Лимит файлов процесса HAProxy, текущие подключения и maxconn.
- Успешность и время установления TCP-соединений Петербург -> каждый выходной VPN-сервер.

Системные TCP-счётчики накоплены с момента старта системы или сетевого пространства; сами по себе большие числа не доказывают текущую проблему. При подозрении на потери нужно сравнить два отчёта с интервалом и учитывать активную нагрузку.

TCP-подключение не измеряет пропускную способность, потери каждого пакета или успешность полного VLESS/Reality сеанса. Быстро открывающийся порт не заменяет проверку через VPN-приложение.

## Проверка с телефона или компьютера

1. Обновить единую подписку и подключиться к первой оплаченной стране.
2. Проверить внешний IP и открыть несколько обычных сайтов.
3. Посмотреть видео или загрузить обычный файл, отметив скорость, зависания и разрывы.
4. Повторить с другими оплаченными странами; полезно сравнить домашний интернет и мобильную сеть.

При оценке скорости учитывать суммарный канал и лимит трафика Петербургского сервера: все страны используют его. Если потребуется точное измерение, отдельно согласовать короткую проверку пропускной способности между принадлежащими владельцу серверами.

## Изменение настроек

Настройки выбираются после анализа отчёта и измерений. Включать BBR, уменьшать MTU, увеличивать все TCP-буферы или менять firewall без обнаруженной причины не требуется. BBR — один из возможных алгоритмов управления перегрузкой, а не универсальное исправление сетевых блокировок.

Для текущей TCP-переадресации через HAProxy IP forwarding и новая схема NAT не нужны.

Источники: [Linux IP sysctl](https://kernel.org/doc/html/latest/networking/ip-sysctl.html), [HAProxy TCP configuration](https://docs.haproxy.org/3.0/configuration.html).
