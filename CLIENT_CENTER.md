# Общий обзор и карточка клиента

## Что добавлено

- `/clients` без параметра сервера переводит в новый `/clients/overview`.
- Список по одному серверу `/clients?server=ID` сохранён вместе с CRUD,
  QR, прямыми ссылками, подпиской и выдачей доступа в ЛК.
- Из общего обзора можно перейти к выбранному серверу; обратно ведёт
  кнопка «Все клиенты» на прежней странице.
- В обзоре одна строка на точное имя/псевдоним 3X-UI: серверы, онлайн,
  суммарный использованный трафик, ближайшее известное окончание.
- Поиск по имени, контакту, логину, комментарию, стране, серверу и группе;
  фильтры подключений и групп. Отдельная адаптация для телефона.
- Карточка открывается по имени или стрелке. Вкладки: серверы, продление,
  заказы, история, кабинеты. Видны комментарии, группы, последняя активность,
  разрешённый доступ и фактический онлайн по последнему ответу 3X-UI.
- Из карточки можно изменить профиль на конкретном сервере, открыть QR/ссылки,
  перейти к заказам, открыть/скопировать ЛК и единую подписку или выдать ЛК.
- Платные успешно выданные серверы и административный доступ считаются отдельно.
  Неоплаченный заказ не становится выданным доступом.

## Точность объединения и ограничения

Объединение выполняется только для полностью одинаковых имён, включая регистр:
`Alex`, `alex` и `Alex ` не смешиваются. Это группировка профилей, а не проверка
личности человека. Если одно имя использовали разные люди, сначала проверьте их
данные. При нескольких кабинетах с одинаковым именем видны все кабинеты и
предупреждение; один токен не выбирается молча.
Выдача нового ЛК из карточки блокируется при коллизии имён, различающихся только
регистром/краевыми пробелами: прежний API выдачи ЛК сопоставляет их без учёта
регистра. Приложение не пытается молча обойти это поведение.

История и кабинеты сопоставляются по точному имени. Переименование профиля
на одном сервере не переименовывает профили на других серверах и не переписывает
заказы/учётные данные. Это сохранённое поведение существующего API.
Комментарий также меняется только у выбранного профиля через прежнее редактирование.

Заказы показывают реальные заказы панели. Административное продление не
создаёт фиктивную оплату или новый заказ. Оно записывается существующим аудитом
PATCH клиента и видно во вкладке «История». Новые записи получают `added_days`,
если передано непустое `days`. Старым записям число дней не приписывается.
История загружается через существующий GET `/audit-logs`, постранично,
с дополнительной точной проверкой имени в `entity_id` после серверного поиска.
История под прежним именем после переименования автоматически не переносится.

Права в подписке и сроки продолжают проверяться backend/3X-UI. Отображение
серверов в обзоре само по себе никому не выдаёт доступ.

## Обновление и сбои

Использованы существующие GET `/servers`, `/clients/{server_id}`, `/accounts`,
`/orders`, `/settings`, `/plans`. Новых API и миграций нет.
Одновременно опрашиваются максимум три VPN-сервера. Отключённые в панели
серверы не опрашиваются; их связанные кабинеты могут остаться в списке.

Раз в 30 секунд, только на видимой вкладке и без открытой карточки/модального
окна, обновляются списки клиентов. Заказы, настройки и кабинеты при каждом
фоновом цикле заново не запрашиваются. Кнопка «Обновить» перечитывает всё.

Сбой одного сервера не скрывает данные остальных. Сохранённые профили такого
сервера помечаются устаревшими, онлайн становится неизвестным. Если не удалось
получить все профили ожидаемых серверов, клиент не объявляется полностью офлайн.
При неполном списке 3X-UI выводится предупреждение.

## Административное продление

В карточке откройте «Продление». Сроки сначала читаются с серверов заново.
Выберите серверы и от 1 до 3650 дней. Предварительная новая дата:

`max(текущая дата окончания, текущее время) + выбранное количество дней`.

Бессрочные профили и отрицательный срок «от первого подключения» этим действием
не сокращаются и не переводятся автоматически на конечный срок. Для них остаётся
прежняя форма редактирования. Недоступный профиль продлить через эту форму нельзя.

Перед первой записью перечитываются все выбранные сроки. Если срок изменился,
запись не отправляется, даты обновляются и требуется новое подтверждение.
При обычном продлении используется прежний PATCH с `days` и `enable: true`:
истёкший/выключенный профиль включается; UUID и лимит трафика не меняются.
Исчерпанный лимит трафика отдельно не сбрасывается.

После каждого PATCH результат перечитывается и проверяются включение и дата.
Для небольшого расхождения часов допускается 2 секунды, не потерянный день.
Потерянный ответ после фактического применения может быть подтверждён чтением,
но повторного PATCH автоматически не будет.

Это не транзакция между VPN-серверами и не глобальная защита от параллельных
действий нескольких администраторов. Между проверкой и PATCH остаётся небольшой
интервал. Если результат неизвестен, сначала обновите сроки и проверьте реальные
даты. Повторное сознательное подтверждение добавляет ещё один период.
После завершённой попытки кнопка заблокирована до явного обновления сроков.

## Установка с резервной копией

Загрузите `client-center-20261102.zip` в `/root/` рабочего сервера сайта:

```sh
cd ~/vpnpanel &&
mkdir -p ~/vpnpanel-backups &&
umask 077 &&
tar --exclude='./.git' --exclude='./frontend/node_modules' \
    --exclude='./frontend/.next' --exclude='./backups' \
    --exclude='*.sock' \
    -czf ~/vpnpanel-backups/pre-client-center-$(date +%Y%m%d-%H%M%S).tar.gz . &&
unzip -o ~/client-center-20261102.zip -d ~/vpnpanel &&
sh scripts/install-client-center.sh
```

До распаковки сохраняется код с `.env`. Установщик отдельно сохраняет базу
в `~/vpnpanel-backups/client-center-ДАТА-ВРЕМЯ/database.dump` и проверяет
её оглавление `pg_restore --list` (не пробное восстановление).
Архивы с настройками и базой приватные: скачайте нужные копии через WinSCP,
не публикуйте их в GitHub.

Затем собираются backend/frontend и выполняются тесты. При ошибке проверки
до пересоздания работающие контейнеры не заменяются. Только после тестов
пересоздаются backend/frontend и перезапускается Caddy; панель кратковременно
недоступна. HAProxy, VPN-монитор и зарубежные Xray не перезапускаются.
Настройки TLS «только предупреждать», firewall, REALITY и маршруты не меняются.

Архив включает совместимые файлы предыдущего этапа онлайн-клиентов, поэтому
получение `online` не зависит от того, был ли отдельно установлен тот ZIP.
Новых npm-зависимостей нет, `package-lock.json` не меняется.

После установки: https://dlgtw.ru/clients/overview . При старом интерфейсе
выполните полное обновление страницы. Сначала проверяйте продление на своём
тестовом профиле, а не на клиенте с действующей оплаченной подпиской.
