# Исправление тестовых сертификатов для Python 3.13

Ошибка `Missing Authority Key Identifier` возникала в сертификатах локального
HTTPS-сервера, который создают тесты. Это не результат проверки сертификатов
Germany, Amsterdam или Poland. Перевыпускать их из-за этой ошибки не требуется.

Python 3.13 включает `VERIFY_X509_STRICT` и `VERIFY_X509_PARTIAL_CHAIN`
по умолчанию. На локальном Python 3.12 эти флаги прежде не включались, поэтому
недостаток тестового сертификата не проявлялся. [Документация Python](https://docs.python.org/3.13/library/ssl.html#ssl.create_default_context)

## Что исправлено

- В тестовые CA и серверный сертификат добавлены идентификаторы ключей SKI/AKI,
  корректные Key Usage, Basic Constraints и назначение Server Auth.
- TLS-тесты явно используют строгие флаги и на Python 3.12, и на Python 3.13.
  Отключение проверки и пропуск падающих тестов не добавлялись.
- Отрицательные сценарии проверяют код реальной причины: истечение срока или
  несовпадение IP, а не случайную ошибку структуры сертификата.
- GitHub Actions проверяет backend на Python 3.13, как рабочий Docker-образ.

Рабочий код API, диагностики, VPN и режим `warning_only` не меняются.
Плохой сертификат по-прежнему является предупреждением, а не блокировкой API.

## Продолжение установки

Судя по выводу с 185 тестами, файлы пакета режима предупреждений уже распакованы.
Установщик остановился на тестах до пересоздания рабочих контейнеров.
Этот небольшой архив нужно распаковать поверх уже подготовленного проекта,
затем повторно запустить тот же установщик.

Загрузите `tls-test-fixture-fix-20261101.zip` в `/root/` сервера сайта:

```sh
cd ~/vpnpanel &&
mkdir -p ~/vpnpanel-backups &&
umask 077 &&
tar --exclude='./.git' --exclude='./frontend/node_modules' \
    --exclude='./frontend/.next' --exclude='./backups' \
    --exclude='./relay/control/*.sock' \
    -czf ~/vpnpanel-backups/pre-tls-test-fix-$(date +%Y%m%d-%H%M%S).tar.gz . &&
unzip -o ~/tls-test-fixture-fix-20261101.zip -d ~/vpnpanel &&
sh scripts/install-xui-tls-verification.sh
```

Не публикуйте резервную копию: она содержит `.env` и может содержать секреты.
Установщик дополнительно сохранит базу, соберёт образ и заново выполнит тесты.
Пропуски `skipped` тестов корневых shell-скриптов внутри Docker остаются
ожидаемыми; TLS-тесты не пропускаются и должны завершиться `ok`.

Не выполняйте `docker compose down -v`, не удаляйте данные и не меняйте
сертификаты зарубежных серверов ради устранения этой ошибки тестового набора.
