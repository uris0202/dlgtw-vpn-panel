# Доменное имя для VPN-входа

## Как это работает

Ссылка подписки остаётся прежней: `https://dlgtw.ru/api/public/subscriptions/...`.
Она загружает список только разрешённых клиенту подключений.

Внутри списка вместо адресов вида `139.100.235.247:24443` будут:

```text
vpn.dlgtw.ru:24443 -> прежний маршрут к VPN-серверу
vpn.dlgtw.ru:24444 -> прежний маршрут к VPN-серверу
vpn.dlgtw.ru:24445 -> прежний маршрут к VPN-серверу
```

Назначение каждого порта сохраняется из текущего `relay/routes.json`.
Порты не переназначаются, UUID, ключи REALITY, SNI, тарифы и права клиента не меняются.
DNS переводит имя `vpn.dlgtw.ru` в IP петербургской машины.
Имя используется как адрес подключения, а не как новый SNI для REALITY.

## 1. Создать DNS-запись

В панели управления DNS домена `dlgtw.ru` создайте:

| Поле | Значение |
| --- | --- |
| Тип | A |
| Имя | vpn (либо vpn.dlgtw.ru, если панель требует полное имя) |
| IP | 139.100.235.247, если это по-прежнему IP петербургского VPN-входа |
| TTL | 300 секунд, если поддерживается вашим DNS-провайдером |
| Проксирование | Выключено / DNS only, если используется Cloudflare |

Не указывайте `https://`, путь или порт в DNS-записи.
Для этой IPv4-настройки не добавляйте AAAA: установщик отклонит неожиданные IPv6-адреса.
DNS-запись основного сайта `dlgtw.ru` сейчас менять не нужно.

Отдельный сайт, сертификат Caddy и запись `vpn.dlgtw.ru` в Caddyfile для этого не нужны:
VPN продолжит работать на существующих портах с прежними настройками REALITY.
Открывать `https://vpn.dlgtw.ru` в браузере для проверки не требуется.

DNS может обновиться не сразу. TTL задаёт срок кэширования, но отдельные приложения
могут хранить результат дольше. Источники:
[TTL](https://developers.cloudflare.com/dns/manage-dns-records/reference/ttl/),
[режим DNS only](https://developers.cloudflare.com/dns/proxy-status/).

## 2. Установить обновление

Архив `vpn-domain-entry-20261031.zip` загрузите в `/root` на сервере сайта.
Это полные файлы для существующего проекта; удалять каталог проекта не нужно.
Сначала выполните резервное копирование кода, затем установку:

```sh
(
set -e
cd ~/vpnpanel
umask 077
mkdir -p ~/vpnpanel-backups
tar --exclude='./frontend/node_modules' --exclude='./frontend/.next' --exclude='./.git' --exclude='./backups' --exclude='./relay/control' -czf ~/vpnpanel-backups/pre-domain-code-$(date +%Y%m%d-%H%M%S).tar.gz .
unzip -o ~/vpn-domain-entry-20261031.zip -d ~/vpnpanel
sh scripts/install-relay-domain.sh vpn.dlgtw.ru 139.100.235.247
)
```

Если петербургский IP уже изменился, замените последний аргумент на фактический IP.
Установщик сохранит маршруты, конфигурацию HAProxy и дамп БД в
`~/vpnpanel-backups/relay-domain-ДАТА` и проверит читаемость оглавления дампа.
Он соберёт только backend, запустит тесты, проверит DNS и обновит backend/Caddy.
Frontend не меняется и не пересобирается; миграция БД не требуется.

Только после успешной проверки DNS и готовности backend будет заменён адрес,
публикуемый в подписке. HAProxy и зарубежные VPN-серверы не перезапускаются.
Сам `haproxy.cfg` при активации домена не меняется.
Перед записью `routes.json` создаётся дополнительная копия актуальных маршрутов в `relay/history`.
Запись атомарная и защищена тем же блокировщиком, что обновление маршрутов через сайт.

При ошибке DNS действующая конфигурация остаётся прежней.
Установщик требует, чтобы все полученные A/AAAA-адреса совпадали с ожидаемым IP:
ошибочная AAAA-запись или включённое CDN-проксирование не будут приняты.
Проверка использует DNS, доступный backend-контейнеру, а не сеть каждого клиента.
Если установка остановилась, не удаляйте контейнеры, базу или `relay/` — пришлите ошибку.

## 3. Обновить приложения клиентов один раз

В VPN-приложении нажмите «Обновить подписку» у уже добавленной единой подписки,
затем переподключитесь. Заново добавлять ссылку подписки не нужно.

После обновления адрес подключения должен стать `vpn.dlgtw.ru`, а порт остаться прежним.
Ранее импортированные IP-профили сами по себе не превращаются в доменные.
До обновления они продолжат использовать прежний IP, пока тот доступен.
Автообновление и автоматическое переподключение зависят от VPN-приложения.

Для проверки содержимого подписки без публикации UUID и токенов:

```sh
cd ~/vpnpanel
docker compose exec -T backend python - 12 --http-only < scripts/diagnose-vpn-subscription.py
```

`12` — существующий ID заказа; используйте нужный заказ.
В выводе `endpoints` должны быть домен и прежние порты. Фактическое VPN-подключение
проверьте также с телефона без другого VPN и с домашнего интернета.

## Если позже изменится IP

Если провайдер заменил IP той же машине, а HAProxy, порты, маршруты и firewall сохранились:

1. Убедитесь, что новый IP действительно назначен машине и VPN-порты доступны.
   Если firewall или доступ к 3X-UI привязан к старому IP Петербурга, разрешите новый адрес.
2. Измените A-запись `vpn.dlgtw.ru` на новый IP.
3. Если на этой же машине находится сайт и его IP тоже изменился, обновите также
   DNS-записи сайта `dlgtw.ru` и используемых им имён. Иначе сайт и загрузка подписки останутся на старом IP.
4. Дождитесь обновления DNS-кэша и переподключите VPN. Иногда требуется перезапуск приложения.

Менять адреса уже импортированных доменных профилей и параметры `public_host` в `routes.json`
при такой смене IP не требуется. Обновлять HAProxy тоже не нужно: он слушает wildcard-адрес,
отдельный от имени, публикуемого в подписке.

Если меняется IP именно зарубежного VPN-сервера, а не входа в Петербурге:
поправьте его URL в разделе «Серверы» и используйте существующую кнопку обновления маршрута.
DNS `vpn.dlgtw.ru` в этом случае не меняется.

При переезде на другую машину одной записи DNS недостаточно: сначала переносится
рабочая конфигурация, открываются порты и проверяется соединение.
При блокировке самого домена или протокола смена IP может не помочь.
Домен не скрывает IP от оператора и не добавляет резервный вход.

## Возврат к IP

Для отмены только доменного адреса без отката остальных маршрутов:

```sh
cd ~/vpnpanel
docker compose exec -T backend python -m app.scripts.set_relay_public_host --public-host 139.100.235.247
```

Укажите актуальный рабочий IP, если он уже другой. После этого клиентам понадобится
обновить подписку, чтобы импортировать IP-профили. Уже импортированные доменные профили
продолжают зависеть от DNS, пока клиент их не обновит.
